# PM-Collab 验收测试大纲（UAT）· 用户视角对照使用手册

版本：V1.0 · 日期：2026-10-08 · 状态：待评审
适用版本：MVP v0.1.0（`pm-collab/使用手册.md`）
视角：**终端用户**（人类前台使用者 + 扮演 AI 通道的文件协议操作者），非接口/代码视角

---

## 1. 验收目的与范围

站在用户角度，逐条核验《使用手册》的承诺是否成立：**照着手册能装起来、用得通、得到保护、留得住痕**。

- 验收对象：手册 §2~§9 描述的全部功能面（项目隔离、五库、交接区、名册/角色、WBS/任务卡、流程门禁、文档版本、卡点、摘要、日志、配置、运维、FAQ）。
- 验收方式：**Web 前台 UI 操作为主**（人类用户视角），**文件协议操作为辅**（以"AI 写交接区文件"的方式模拟 AI 通道，验证系统识别入库）。
- 与既有测试的关系：此前 L0~L4 是服务层/接口验证；本大纲是**用户验收层（UAT）**，验收用例可直接落到 `playbook_dual.py`/剧本脚本的 UI 化改造或人工冒烟清单。

## 2. 验收对象与前置条件

| 项 | 值 |
| --- | --- |
| 被测部署 | 本地 `http://127.0.0.1:8731`（或手册 §2 安装步骤全新部署 8000） |
| 登录账号 | `admin / 首次启动随机口令`（手册 §2.4） |
| 前置 | `seed.py` 已初始化；`PM_WATCHDOG_ENABLED=true`（默认）；前端构建产物托管可用 |
| 数据卫生 | 每个验收场景使用独立项目 `UAT-<场景>-<日期>`，验收后保留或归档 |

## 3. 验收用例分级

| 级别 | 定义 | 准出要求 |
| --- | --- | --- |
| P0 | 阻断性：手册核心承诺、主链路必经 | 必须 100% 通过 |
| P1 | 重要：承诺功能可用、数据正确 | 通过率 ≥ 95%，缺陷须有修复计划 |
| P2 | 一般：体验、边界、FAQ 场景 | 通过率 ≥ 90%，缺陷登记跟踪 |

## 5. 手册承诺核验清单（关键规则 + 已知差异）

### 5.1 手册 §6 关键规则表（代码强制）逐条核验

| 规则 | 验收方法 | 对应用例 |
| --- | --- | --- |
| 阶段不可跳过 | 尝试 S1→S3 | UAT-06-05 |

| 文档命名 + 哈希校验 | 合规/不合规登记、篡改校验 | UAT-07-01/02/04 |
| 门禁签字必须人类 | AI 登录代签 | UAT-06-04 |
| 测试不通过不得验收 | 测试登记未通过后推进 | UAT-06-07 |
| AI 操作须经人类授权（规范） | 交互日志复核 AI 动作（建项目/编辑项目/名册/跨项目读） | UAT-08-05 |

### 5.2 手册承诺 vs 实测差异（验收必测回归点）

| 差异 | 手册表述 | 实测行为 | 影响 | UAT 处置 |
| --- | --- | --- | --- | --- |
| DEF-05 | §4.1「编辑项目 → 改状态（编号不可改）」 | `PUT /api/projects` 带 status 字段全部 422（ProjectIn 无 status） | **用户按手册操作"改状态"必失败** | 验收前修复或降级：大纲按手册承诺验收，失败即**P0 缺陷阻断准出** |
| DEF-04 | §4.9「登记文档条目…系统按命名规则校验」+ 新逻辑"未给路径默认落五库" | 不带 path 登记默认文件名不合规 → 422 | 用户少填路径时被拒且提示指向命名规则（误导） | 验收场景 UAT-07-09；修复前按 P0 缺陷跟踪 |
| O-05~O-08 | §6 已补"AI 授权策略（规范层面）"：AI 应经授权后执行 | 服务端未做硬性拦截（AI 可建项目/编辑/删成员/跨项目读） | 规范已写入手册，代码拦截待确认 | 验收按手册规范执行：核对**审计留痕完整性**（UAT-08-05），代码层拦截不阻塞 UAT |
