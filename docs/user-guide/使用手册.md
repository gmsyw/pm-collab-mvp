# PM-Collab 人机共用项目管理软件 · 使用手册

> 适用版本：开源发布版 v0.1.0
> 定位：人类与 AI 共用同一份数据、同一套流程、同一套留痕。所有功能均以**项目**为单位独立管理，切换项目即切换数据视图。
> 开源版重点（相较内部版）：**无硬编码密钥/口令**；首次启动随机生成管理员口令与 JWT 密钥；新增**修改密码**功能；令牌与脚本均走环境变量，无明文凭据泄露风险。

## 1. 产品简介

PM-Collab 把《项目管理 AI（PM-AI）需求规格书》落到可运行软件。它解决的核心问题是：**人类和 AI 在同一个项目里协作，但用同一套任务卡、同一套流程门禁、同一套留痕审计**，而不是各写各的、事后对不齐。

系统以「五库 + 交接区」托管所有产物，以「任务卡状态机 + 流程门禁」驱动进度，以「追加日志」保证可追溯。MVP 默认 **SQLite 单机零依赖**部署，设置环境变量即可切换 PostgreSQL 16。

### 谁在用

- **人类成员（人-A）**：通过 Web 前台创建/设置/查看/修改一切；流程门禁的签字权专属人类。
- **AI 成员（AI-R）**：通过「交接区文件协议」或「服务层 API」与人类协作，可派单、回执、完成、评审输入、提出卡点，但**不能代人类签字**。

## 2. 快速开始

### 2.1 环境要求

- Python 3.11+
- Node.js 18+（仅前端开发/构建需要）
- Windows / macOS / Linux 均可

### 2.2 后端安装与启动

```powershell
cd pm-collab
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt

# 初始化数据库（建表 + 追加日志触发器 + 种子数据）
.\.venv\Scripts\python scripts/seed.py

# 启动服务（自动托管五库与交接区、启动 watchdog 监听与每日摘要定时任务）
.\.venv\Scripts\python -m uvicorn server.app.main:app --host 127.0.0.1 --port 8000
```

启动成功后你会看到：

```
[startup] 已为 N 个项目建立独立资料目录（data/projects/<项目编号>/）
[startup] PM-Collab 人机共用项目管理软件 v0.1.0 @ 127.0.0.1:8000
[watchdog] 交接区同步 ...
```

### 2.3 前端启动

**方式 A：仅使用（推荐）** — 前端构建产物由后端一并托管，启动后端后直接访问即可：

- Web UI：`http://127.0.0.1:8000/`
- API 文档（交互式）：`http://127.0.0.1:8000/swagger`（OpenAPI 描述：`/openapi.json`；注意 `/docs` 已被前端「文档库」页占用，故 Swagger 挂在 `/swagger`）

**方式 B：前端开发模式**（需要改界面时）：

```powershell
cd web
npm install
npm run dev      # http://localhost:5173，已配置 /api 与 /ws 代理
npm run build    # 产物输出到 web/dist，由后端自动托管
```

### 2.4 默认账号

| 角色 | 账号 | 初始密码 |
| --- | --- | --- |
| 初始人类管理员 | `admin` | **首次启动由系统生成一次性随机密码**，打印在启动控制台（形如 `初始密码: xxxx`）。该密码仅显示一次，登录后请**立即通过右上角「修改密码」更换**。 |

> 安全须知：开源版**不在源码/配置中写死任何口令或密钥**。若 `PM_BOOTSTRAP_PASSWORD`/`PM_SECRET_KEY` 未显式配置，系统在首次启动（库内尚无 `admin`）时随机生成并写入 `.env`（`.env` 已被 `.gitignore` 排除，请勿提交）。升级老库不会覆盖既有密码。

登录后所有页面的数据都围绕「当前项目」展开。

## 3. 核心概念

### 3.1 项目隔离

每个项目拥有一套**完全独立**的资料目录：`data/projects/<项目编号>/`，内含独立的五库与交接区。数据库侧所有实体（成员、角色卡、任务卡、文档、版本、交接单、卡点）均带 `project_id`，接口按「当前项目」过滤。切换项目即切换全部数据视图，资料互不串味。

### 3.2 五库（文件托管）

软件自动维护，无需手工建目录：

| 库 | 子目录 |
| --- | --- |
| `01_项目库` | 项目章程 / 成员名册与角色卡 / 需求基线 / 计划与里程碑 / 变更单 / 评审记录单 |
| `02_交付物` | 01_需求 / 02_设计 / 03_验收 / 04_测试 / 代码 |
| `03_日志` | 交互日志 / 任务台账 / 问题与风险台账 / 日报周报 |
| `04_模板` | 角色卡 / 设计文档 / 评审记录单 / 测试记录单 / 版本台账（全局共享） |
| `05_版本库` | 发布日志 / archive |

### 3.3 交接区（人机协同总线）

每个项目下 `交接区/` 含 **7 个槽位**（6 目录 + `交接单.json`）：

`派单` · `回执` · `完成` · `评审输入` · `评审输出` · `卡点` + `交接单.json`

这是人类与 AI 之间唯一的「文件级」协作通道（详见第 5 节）。

### 3.4 组织与权限（名册 + 角色卡）

- **成员名册**：人类与 AI 成员统一建档、统一编号。
- **角色卡（8 字段）**：`code / role_type / duty / negative_list / permission_level / data_boundary / reports_to / downgrade_plan`，权限等级 L1–L4。

### 3.5 任务卡与 WBS

- **任务卡（14 字段）**：含目标、输入、交付物、验收标准、人类负责人、AI 执行者、起止、优先级、状态等；受任务状态机约束。
- **WBS 四层**：里程碑 → 工作包 → 任务 → 子任务，层级归属自动联动。

### 3.6 流程门禁

8 阶段状态机 + 4 道门禁签字台。阶段不可跳过；无门禁签字不放行；测试/评审证据缺失不得推进。签字权**专属人类**。

### 3.7 卡点信号

AI 或系统发现风险（如文档哈希不匹配、阻塞超时）时抛出卡点，进入队列并实时推送到前台，等待人类处理。

### 3.8 每日摘要

每天 08:30 自动生成项目度量（里程碑进度、偏差、逾期、核心指标），可本地留痕或推送到飞书（可选）。

### 3.9 追加日志

所有关键写操作自动写入**只增不改、不可删**的交互日志，形成完整证据链。

## 4. 人类前台操作指南

登录后，界面顶部有**当前项目选择器**。先选/建项目，再在其下操作一切。

### 4.1 项目

- **新建**：顶部「新建项目」→ 填写编号、名称、负责人、描述。
- **编辑**：选中项目后点「编辑项目」→ 改名称/描述/负责人/状态（编号不可改，保可追溯）。
- 所有后续页面的数据都只属于当前项目。

### 4.2 看板 Dashboard

- 项目度量概览（里程碑进度、偏差、逾期、4 项核心指标），ECharts 图表。
- 每日摘要查看入口。

### 4.3 成员名册 Members

- **查看**：当前项目成员列表（含全局默认成员）。
- **新增/编辑/删除**：维护人类与 AI 成员（编号、姓名、类型、状态、汇报对象）。
> 成员归属当前项目，跨项目不可见。
> 新建项目会自动克隆 default 的名册/角色卡为「带项目编号前缀」的私有副本，各项目可独立调整、互不污染；尚未生成私有副本的空项目会回退显示 default 模板（隔离仍然生效）。

### 4.4 角色卡 Roles

- **查看/新增/编辑/删除**：8 字段录入，含负面清单、权限等级 L1–L4、数据边界、汇报对象、降级预案。
> 角色卡同样以项目为单位隔离。

### 4.5 WBS 分解 Wbs

- **里程碑 / 工作包**：创建、编辑、删除、查看。
- **子任务**：创建、状态迁移、删除；点「编辑子任务」修改字段。
- 自动生成该项目的 WBS 树与目录结构。

### 4.6 任务卡 Tasks

- **创建**：填写 14 字段任务卡，可指派人类负责人与 AI 执行者。
- **编辑**：点「编辑任务卡」修改任意字段。
- **状态迁移**：待办 → 进行中 → 待评审/阻塞/取消/返工 → 通过 → 关闭（非法迁移被拒）。
- **证据/投喂**：补充证据路径与完成摘要；可将任务投喂给 AI（写入交接区 `派单/`）。

### 4.7 交接区与卡点 Handoff

- **交接单**：查看当前项目全部交接单及其 4 态（待投喂 → 已投喂 → 已回收 → 已闭环）；可推进、回收、闭环。
- **新建交接单**：点「+ 新建交接单」主动发起（人类侧）。
- **卡点信号**：查看队列；标记处理。点「+ 新建卡点信号」主动抛出卡点（人类侧）。
- 文件 ↔ 库双向同步：交接区文件变化由 watchdog 实时入库，状态按状态机合法方向更新。

### 4.8 流程门禁 Governance

- **查看/推进阶段**：8 阶段状态机逐步推进。
- **登记测试/评审**：上传证据。
- **签字**：门禁由人类签字通过或驳回（AI 不可代签）。
- **追加日志**：查看本项目的交互留痕。

### 4.9 文档与版本 Docs

- **登记文档条目**：登记到本项目五库，系统按命名规则校验并算哈希。
- **编辑/删除**：修改条目元信息；删除同时尝试删除正文文件。
- **哈希校验**：点击校验，哈希不匹配即告警并自动抛卡点。
- **版本台账**：查看；「+ 登记版本」手动新增；「基线化」仅评审通过版本可提升基线。
- **需求条目库**：追溯矩阵左端（需求 → 设计 → 实现 → 用例 → 结果）。

### 4.10 账户与安全（修改密码）

开源版账号体系面向「个人单机部署」，但已补齐企业级安全基座：

- **修改密码**：登录后，点击界面右上角用户名右侧的「修改密码」按钮，输入旧密码与新密码即可。新密码需满足最小强度（不少于 8 位，建议含大小写+数字）。
- **旧令牌即时吊销**：改密成功后，所有此前签发的 JWT 立即失效（系统写入 `token_valid_from`，`iat` 早于该时间的令牌返回 401）。前端会自动清除本地令牌并跳回登录页，已登录的其他设备/脚本需重新登录。
- **忘记密码**：见 [第 10 节](#10-常见问题) Q6。

> AI 成员（AI-R）通过「交接区文件协议」或持与人类一致的 JWT 调用 API，也需遵守上述口令策略；脚本类调用一律通过环境变量传入口令，源码中不含明文凭据。

## 5. AI 通道使用指南（文件协议）

AI 与主系统的标准协作方式是**文件协议**：AI 读写当前项目的 `交接区/` 目录与 `交接单.json`，由系统监听入库。AI 也可持 JWT 直接调用服务层 API（与人类等价）。

> 路径示例：`data/projects/<项目编号>/交接区/`

### 5.1 七槽位用途

| 槽位 | 谁写入 | 用途 |
| --- | --- | --- |
| `派单` | 人类 / PM-AI | 任务派发文件，命名 `任务编号_派单_名称_Vx.md` |
| `回执` | AI | AI 复述交付物与验收标准，参数缺失只问不猜 |
| `完成` | AI | 完成摘要，供系统回收并登记版本台账 |
| `评审输入` | 人类 | 提供给 AI 的评审材料 |
| `评审输出` | AI | AI 的评审结论 |
| `卡点` | AI / 系统 | 风险或阻塞信号 |
| `交接单.json` | 双方 | 交接单权威台账（见下） |

### 5.2 交接单 JSON 结构

AI 可直接编辑 `交接单.json` 来创建/推进交接单（watchdog 监听后入库）：

```json
{
  "project": "<项目编号>",
  "updated_at": "",
  "orders": [
    {
      "code": "H001",
      "sender": "人类",
      "receiver": "PM-AI",
      "zone": "派单",
      "payload_path": "交接区/派单/T04_派单_登录模块_V1.md",
      "status": "待投喂",
      "task_code": "T04",
      "content_hash": ""
    }
  ]
}
```

- **状态机（4 态，只允许单向推进）**：`待投喂 → 已投喂 → 已回收 → 已闭环`。
- 非法（倒退/跳变）状态会被忽略并记入冲突列表，保证双写一致。
- AI 可写字段：`code / sender / receiver / zone / payload_path / status / task_code / content_hash`。

### 5.3 AI 完成回写格式

AI 在 `完成/` 目录产出的摘要文件，系统按以下键解析（其余行作为正文摘要）：

```
任务编号: T04
执行者: PM-AI
证据路径: data/projects/P001/02_交付物/03_验收/login_ok.md
交付路径: data/projects/P001/02_交付物/代码/login.py
版本: V1.0

（此处写完成摘要正文……）
```

系统据此：推进任务、登记一条「版本台账」（版本不覆盖，每次新增记录）、并写入交互日志。

### 5.4 卡点抛出

AI 在 `卡点/` 写入或在 `交接单.json` 标注后，系统生成卡点信号进入队列，实时推送前台等待人类处理。典型触发还包括：文档哈希校验不匹配（系统自动抛卡点）。

### 5.5 文档命名规则（代码强制）

登记到五库的文档必须符合命名规范，否则被拒：

```
项目-类型-名称-V主.次.修订.扩展名
```

- 正则：`^.+-.+-.+-V\d+\.\d+\.\d+\.[A-Za-z0-9]+$`
- **类型词**须取自词表：章程 / 名册 / 角色卡 / 需求基线 / 计划 / 变更单 / 设计文档 / 测试报告 / 验收记录 / 交互日志 / 任务台账 / 问题台账 / 日报 / 周报 / 模板 / 版本台账 / 发布日志
- 示例：`PM-Collab-设计文档-登录模块-V1.0.0.md`
- 状态**不**入文件名；版本变更以 `V主.次.修订` 表达。
- 登记文档时若未传 `path`，系统按《文档组织方案》§4 自动生成合规文件名：类型词优先取文档 `category`，未提供则按 `library` 映射（01_项目库→模板、02_需求库→需求基线、03_设计库→设计文档、04_测试→测试报告、05_运维→发布日志）；建议显式传 `category` 以获得准确类型词。

## 6. 关键规则（人类与 AI 须知）

以下规则由代码强制，不遵守会被系统拒绝：

| 规则 | 说明 |
| --- | --- |
| 阶段不可跳过 | 8 阶段必须顺序推进，无门禁签字不放行 |
| 任务非法迁移被拒 | 如 关闭→待办 等倒退/跳变被拒 |
| 无证据不得置「通过」 | 关闭须有完成摘要 |
| 追加日志只增不改不可删 | 形成不可篡改证据链 |
| 交接单 4 态单向 | 文件↔库双向同步，冲突不计 |
| 文档命名 + 哈希校验 | 命名不合规被拒；哈希不匹配即告警抛卡点 |
| 门禁签字必须人类 | AI 不可代签 |
| 测试不通过不得验收 | 测试证据缺失阻塞推进 |
| AI 操作须经人类授权 | AI 可在「人类下达指令」或「执行前经人类确认」前提下执行（含建项目 / 编辑项目 / 管理名册 / 读跨项目 WBS 等）；所有 AI 写操作均记入审计留痕，人类可在交互日志复核 |

> **AI 授权策略（规范层面，非代码强制）**：依据双视角回归测试 V1.4 的观察项 O-05~O-08，AI 成员当前在服务端未做硬性写操作拦截。按产品原则，AI 应在获得人类指令、或执行前经人类确认的前提下操作；所有 AI 动作通过追加日志 / 审计留痕（actor 为 AI 成员标识）可追溯。该策略以手册规范 + 审计留痕保障，是否升级为代码层拦截待需求书确认。

## 7. 配置与环境变量

通过 `PM_` 前缀环境变量或 `.env` 文件覆盖（前缀 `PM_`，如 `PM_PORT=8080`）：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `PM_DATABASE_URL` | `sqlite:///data/pm_collab.db` | 切 PG：`postgresql+psycopg://user:pwd@host:5432/pmcollab` |
| `PM_DATA_DIR` | `pm-collab/data` | 五库与交接区根目录 |
| `PM_SECRET_KEY` | 占位默认值（首次启动自动随机生成） | JWT 签名密钥；**留空/占位值时首启随机生成并写入 `.env`**，切勿提交 `.env` |
| `PM_JWT_EXPIRE_MINUTES` | 720 | 登录有效期 |
| `PM_DAILY_DIGEST_HOUR/MINUTE` | 8 / 30 | 每日摘要定时 |
| `PM_WATCHDOG_ENABLED` | true | 交接区监听开关 |
| `PM_SCHEDULER_ENABLED` | true | 定时任务开关 |
| `PM_FEISHU_WEBHOOK` | 空 | 可选推送；留空则仅本地日志留痕 |
| `PM_BOOTSTRAP_USERNAME/PASSWORD` | admin / （首启随机生成） | 初始人类成员；留空则系统生成一次性口令（仅库内无该成员时生效） |
| `PM_COLLAB_PASSWORD` / `PM_COLLAB_USER` | （无默认） | **运维脚本（smoke / acceptance_flow / close_tasks）登录所用**：运行时通过环境变量传入，源码不含明文；未设置会报错退出 |

> 数据库选型：本机未装 PostgreSQL 时默认 SQLite 单机运行；同一套 ORM/迁移代码，设置 `PM_DATABASE_URL` 即启用 PG，触发器与 REVOKE 按方言自动适配。

> 端口说明：实际监听端口由启动命令 `uvicorn ... --port <端口>`（或反向代理）决定；`PM_PORT` 仅影响启动横幅显示的项目地址，**不控制**实际监听端口。手册示例的 8000 为默认显示值。

## 9. 开源与安全

本项目以 **MIT 许可证**开源（见仓库根 `LICENSE`），面向个人单机部署。安全相关要点：

- **无硬编码凭据**：源码、配置、脚本、测试、文档中均不含默认口令或密钥字面量（`REMOVED-FOR-OPENSOURCE` 等已全部清除）。
- **首次启动随机口令**：新库首次启动（库内尚无 `admin`）由系统生成一次性随机密码并打印在控制台；登录后请立即「修改密码」。
- **JWT 密钥自生成**：`PM_SECRET_KEY` 仍为占位默认值时，首启随机生成并写入仓库根 `.env`（已被 `.gitignore` 排除），请勿提交 `.env`。
- **密钥/口令可显式配置**：通过 `PM_SECRET_KEY`、`PM_BOOTSTRAP_PASSWORD` 环境变量覆盖（生产环境推荐显式设置强值）。
- **改密即吊销旧令牌**：见 [4.10](#410-账户与安全修改密码)。
- **数据不入库**：五库正文文件存于 `data/`（已被 `.gitignore` 排除），仓库仅含索引元数据；发布时不会泄露真实项目资料。
- **第三方依赖许可**：清单见 `docs/third-party-licenses.md`，默认依赖均为宽松许可（MIT/Apache/BSD/PSF），无 GPL/AGPL 传染性条款。

> 责任声明：发布权归作者所有；请勿将含个人/客户私密数据的 `data/` 目录提交到公开仓库。

## 10. 常见问题

**Q1：打开页面是空白/旧界面？**
后端会托管最近一次 `npm run build` 的 `web/dist`。改了前端后请重新 `npm run build` 并重启后端；开发期直接用 `npm run dev`（5173，代理到后端）。

**Q2：切换项目后数据没变？**
所有读写都按「当前项目」过滤。确认顶部项目选择器已切换到目标项目；新成员/角色卡/任务卡默认归属当前项目。

**Q3：AI 改了交接区文件但库里没更新？**
确认 `PM_WATCHDOG_ENABLED=true`（默认开）。状态机非法推进会被忽略并记冲突。可直接在前台「交接区 → 同步」按钮触发一次同步。

**Q4：文档登记被拒？**
检查命名是否符合 `项目-类型-名称-V主.次.修订.扩展名`，且类型词在词表内。

**Q5：门禁一直推进不了？**
缺少测试/评审证据，或上道工序未签字。签字权专属人类，需人工在「流程门禁」页签字通过。

**Q6：忘记管理员密码？**
- 路径①（仅首次初始化生效）：`PM_BOOTSTRAP_USERNAME/PASSWORD` 只在**库内尚无该成员时**创建；若管理员已存在，修改后重启**不会覆盖**已有密码。
- 路径②（立即生效）：直接用数据库/脚本更新 `members` 表对应记录的 `password_hash`（如 `UPDATE members SET password_hash=<新哈希> WHERE username='admin'`），重启后即可凭新密码登录。
- 路径③（官方重置命令，立即生效）：在 `pm-collab/` 目录下执行 `python -m scripts.reset_password`，输入 `y` 确认后，系统生成随机新口令并打印到控制台（仅一次性显示，请妥善保存）；重置同时吊销所有现有登录会话（旧 JWT 即时失效）。源码零硬编码口令，与需求大纲 AC-U2 口径一致。
